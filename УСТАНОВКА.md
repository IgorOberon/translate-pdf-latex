# Установка и запуск на новом компьютере

Инструкция для Windows 10/11, PowerShell. Все команды выполняются из папки
скилла. Пример — `D:\Tools\translate-pdf-latex`; замените пути на свои.
Другие скиллы для обычного прогона не нужны.

Название с выпуска beta.2 — `translate-pdf-latex` (ранее `translate-en-ru-pdf-latex`).
Новый архив распаковывайте отдельно; старые задания и venv не переносите поверх
новой версии. В клиенте держите только одну активную копию этого скилла.
Список отдельной коллекции: [26 дополнительных скиллов](docs/COMPANION_SKILLS.md).
Языки MT задаются параметрами, но простой books/skeleton пока EN→RU;
проверенный OCR-сценарий — DE→RU. Подробности и границы — [README](README.md).

## 1. Распаковать архив

Распакуйте **всю** папку `translate-pdf-latex`, а не один `SKILL.md`.
Лучше короткий путь: это уменьшает риск ограничения длины путей ML-пакетов.
Книги и результаты держите отдельно от программ.

```powershell
Set-Location 'D:\Tools\translate-pdf-latex'
```

Можно открыть эту папку как проект в ИИ-агенте: достаточно прочитать `SKILL.md`
и запускать программы, без отдельной регистрации скилла. Для автоматического
выбора скилла установите всю папку в каталог скиллов клиента по его инструкции.
После перемещения папки venv создаётся заново, чужой venv не переносится.

## 2. Установить основные программы

Установщики запускаются отдельно, с вашего согласия:

| Программа | Для чего и откуда |
|---|---|
| Python 3.10+, проверенная версия 3.12 | [python.org](https://www.python.org/downloads/windows/); добавьте Python в PATH |
| Pandoc | Текст → LaTeX; [установка](https://pandoc.org/installing.html) |
| MiKTeX либо TeX Live с XeLaTeX | Сборка PDF; [MiKTeX](https://miktex.org/howto/install-miktex) |
| LM Studio | Сервер локальной модели; [загрузка](https://lmstudio.ai/download) |

В MiKTeX разрешите доустановку пакетов при первом тесте или установите их заранее.
Нужны шрифты **CMU Serif / CMU Sans Serif / CMU Typewriter Text** (`cm-unicode`),
`fontspec`, `polyglossia`, `csquotes`, `amsmath`, `amssymb`, `mathtools`, `mathrsfs`,
`graphicx`, `array`, `booktabs`, `longtable`, `microtype`, `hyperref`, `fancyhdr`,
`truncate`. Чужой LaTeX-каркас может требовать LuaLaTeX и свои шрифты.

После установки откройте **новое** окно PowerShell:

```powershell
python --version
where.exe python
pandoc --version
xelatex --version
```

Если `python` открывает Store или молчит, это может быть WindowsApps-заглушка.
Установите настоящий Python; проверьте также `py --version`.
Нужная RAM/VRAM зависит от модели, квантования, контекста и OCR: универсального
обещания «хватит 8 ГБ» нет. Начинайте с одного запроса. CPU подходит для небольшого
теста, но полный перевод будет заметно медленнее.

## 3. Создать окружение

```powershell
Set-Location 'D:\Tools\translate-pdf-latex'
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

`Bypass` действует только для этого запуска, не меняет постоянную политику.
Скрипт создаёт `venv`, ставит `requirements.txt` и запускает диагностику.
Он **не** устанавливает Pandoc, TeX, LM Studio, модели или OCR-движки.
В конце пока возможна ошибка «сервер не отвечает»: сервер настраивается далее.

Ручной вариант вместо скрипта (для другой версии Python замените `-3.12`):

```powershell
py -3.12 -m venv venv
.\venv\Scripts\python.exe -m pip install --upgrade pip
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

Дальше вызывайте явный `venv\Scripts\python.exe`, чтобы не попасть в другое окружение.

## 4. Настроить модель

1. В LM Studio скачайте GGUF модели Hy-MT2, например 7B:
   [коллекция Tencent](https://huggingface.co/collections/tencent/hy-mt2).
   Квантование выбирайте по памяти, с запасом под контекст.
2. Developer → **Start server**, порт `1234`.
3. **Serve on Local Network выключено**: оставьте сервер только локальным.
   Простой локальный режим конвейера не передаёт API-ключ; обязательная авторизация
   сервера требует отдельной настройки. Не открывайте такой сервер в сеть.
4. Включите **Just in Time Model Loading**, чтобы модель могла вернуться после
   извлечения. Для выгрузки перед GPU-OCR нужен CLI `lms`; проверка: `lms --help`.
5. Не держите вместе на GPU MinerU и модель перевода. Оркестратор выгружает
   LM Studio перед GPU-OCR. Если память занимает другой сервер (Ollama/llama.cpp),
   его остановку нужно согласовать отдельно.

Выгрузка проверяется через `lms ps --json`; после MinerU конвейер ждёт завершения
его отслеженных дочерних процессов. Если очистка не подтверждена, переход к MT
блокируется. `psutil` обязателен (входит в `requirements.txt`). Другой сервер
не останавливается автоматически. `--vram-limit` не заменяет выгрузку модели.

Официальные инструкции: [сервер](https://lmstudio.ai/docs/developer/core/server),
[настройки JIT](https://lmstudio.ai/docs/developer/core/server/settings).

Узнайте **точный ID** модели:

```powershell
(Invoke-RestMethod 'http://127.0.0.1:1234/v1/models').data | Select-Object id
```

Умолчание — `hy-mt2-7b`. Если у вас другой ID, сохраните в редакторе
`local-model.json` (UTF-8 **без BOM**), заменив `EXACT_MODEL_ID`:

```json
{"host":"http://127.0.0.1:1234", "model":"EXACT_MODEL_ID", "mode":"hymt", "parallel":1}
```

Для общей модели — `"mode":"generic"`. Нужен OpenAI-совместимый API,
не веб-страница чата. Секреты в JSON не помещать. Контекст подбирайте по модели
и глоссарию; `context / parallel` не является универсальным лимитом запроса.
Полировка и облачная замена по умолчанию выключены.

Уже работает другая локальная модель? Для первого Markdown-теста можно оставить
её на GPU и указать её endpoint и точный ID в `local-model.json`, например
`http://127.0.0.1:8080` и `mode: generic`. Во всех командах `doctor.py` используйте
те же `--host`/`--model`, а в `init` — `--settings .\local-model.json`.
Ошибка установщика про отсутствующий сервер на 1234 при этом ожидаема: она не
означает неудачную установку Python-пакетов. Не загружайте вторую модель для этого
теста; перед последующим GPU-OCR отдельно согласуйте выгрузку первой.

## 5. Проверить установку и маленький перевод

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\verify_package.py
.\venv\Scripts\python.exe -X utf8 tests\run_smoke.py
.\venv\Scripts\python.exe -X utf8 scripts\doctor.py --host http://127.0.0.1:1234 --model hy-mt2-7b
```

Первая команда сверяет файлы с SHA-256 манифестом; это не подпись автора.
Сознательная правка шаблона даст `CHANGED`. Не переписывайте манифест ради
зелёного статуса. Дополнительные локальные файлы не проверяются.
Тесты заканчиваются `SMOKE PASSED`, не скачивают модель и не переводят книгу.
Процессные тесты изолированы: не выполняют глобальную очистку MinerU и не
останавливают чужие задания. Таймаут проверяется только на собственном
искусственном дочернем процессе.

Замените `hy-mt2-7b` на свой точный ID, если он отличается.
Доктор: `0` — выбранные проверки пройдены; `1` — отсутствует обязательное или
проверка завершилась ошибкой; `2` — предупреждения/пропущенные проверки.
Нет Tesseract/MinerU — Markdown-тесту это не мешает, но нужный для PDF движок
всё равно надо установить. `/v1/models` подтверждает доступность API и ID,
но не успешную генерацию или вместимость контекста: для этого нужен пробный перевод.
`doctor.py --quick` пропускает TeX-компиляцию и опрос сервера.

Первое задание — синтетический текст без PDF/OCR. Папка `demo-01` **ещё не существует**:

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py init assets\quickstart.md --out 'D:\Translations\demo-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py plan 'D:\Translations\demo-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py run 'D:\Translations\demo-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py status 'D:\Translations\demo-01'
```

При другом ID добавьте `--settings .\local-model.json` к `init`.
Результат: `D:\Translations\demo-01\work\book-001\quickstart.ru.pdf`.
Проверьте русский текст, `F = ma`, число 2, сноску и переход раздела.
Первый запрос может ждать загрузки модели; не запускайте второй экземпляр.

## 6. Выбрать извлечение и перевести книгу

Для EPUB/DOCX/MD PDF-OCR не нужен. Для PDF установите **один** подходящий движок
в этот же venv, не весь набор:

| PDF | Поле `extract` в JSON | Установка |
|---|---|---|
| Сложная вёрстка / обычный скан | `auto` (умолчание) или `scan` | `.\venv\Scripts\python.exe -m pip install marker-pdf` |
| Много формул | `math` | `.\venv\Scripts\python.exe -m pip install "mineru[core]"` |
| Цифровой текст без важных формул и векторных рисунков | `digital` | `.\venv\Scripts\python.exe -m pip install pymupdf4llm` |

GPU-движки скачивают дополнительные зависимости и веса. CUDA/драйвер проверяются
отдельно: [MinerU](https://github.com/opendatalab/MinerU),
[Marker](https://github.com/datalab-to/marker). Фрактура требует Tesseract `deu_latf`
и профиля структуры по `PIPELINE_REFERENCE.md`, а не простого выбора `auto`.

Для MinerU добавьте `"extract":"math"` в JSON настроек. При ручных старых
командах вместо диспетчера активируйте venv или добавьте `venv\Scripts` в PATH.
Перед PDF-прогоном проверьте **выбранный** извлекатель (для Marker — `auto`
или `scan`, для простого цифрового PDF — `digital`):

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\doctor.py --extract math --host http://127.0.0.1:1234 --model hy-mt2-7b
```

Без `--extract` доктор проверяет базовый режим `none` для MD/EPUB, а не готовность
любого PDF-OCR. Указанный, но отсутствующий движок теперь даёт ошибку, не предупреждение.
Сначала испытайте небольшой фрагмент своей книги, затем:

Для проверки возьмите 1–3 страницы с формулой, рисунком, таблицей и сноской.
Проверьте их присутствие в новом PDF: зелёная компиляция сама по себе недостаточна.
MinerU может исключать сноски из `.md`, сохраняя их в `_content_list.json`.
Теперь конвейер сохраняет исходники и создаёт `.prepared.md` + `.prepare.json`:
восстанавливает однозначные сноски и прямоугольные HTML-таблицы без объединений.
Не удаляйте JSON извлечения. `MinerU structure not accepted` означает необходимость
проверки указанного OCR-фрагмента; не обходите её `--no-clean` или удалением сноски.
Сложные таблицы и неоднозначные ссылки не исправляются догадкой.

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py init 'D:\Books\book.pdf' --out 'D:\Translations\book-01' --settings .\local-model.json
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py plan 'D:\Translations\book-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py run 'D:\Translations\book-01'
```

Если хватает умолчаний, уберите `--settings`. Для очереди укажите папку книг:
подпапки не обходятся, MD/TXT/HTML передавайте отдельными файлами.
`glossary.md` рядом с книгой используется автоматически. Готовый OCR-проект или
LaTeX-каркас: [правила маршрутов](docs/LOCAL_AGENT.md). Books/skeleton сейчас EN→RU;
подготовленный OCR по умолчанию DE→RU. Нестандартные внешние ресурсы соберите
в самодостаточный проект до `init`.

## 7. Статус и продолжение

`run` занимает терминал до завершения; его окно нужно оставить открытым.
Для долгого задания на Windows вместо `run` используйте:

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py start 'D:\Translations\book-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py background-status 'D:\Translations\book-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py status 'D:\Translations\book-01'
```

`start` отправляет однократную задачу Планировщика от текущего пользователя;
после успешной отправки окно можно закрыть. Квитанция отправки ещё не означает
готовый PDF: дождитесь `done` в обоих статусах. Остановка — `pipeline.py stop JOB`.
Выход из учётной записи и перезагрузка не покрываются. Внешний сервер LM Studio
должен продолжать работать; запуск собственного управляемого сервера, его профиль
и ограничения описаны в [BACKGROUND_RUN.md](docs/BACKGROUND_RUN.md).

- `done`: пути новых PDF перечислены в статусе; приёмка техническая, не научная.
- `running`: ждать, не запускать дубль. Статус — не процент перевода книги.
- `needs_attention`: прочитать указанный лог в `JOB/logs`, устранить причину.
- `interrupted`: убедиться, что живого дочернего процесса нет, повторить `run`.
- `stale`: разобраться с изменением кода/настроек/файлов.

После устранения ошибки повторите `run JOB` либо `start JOB` для фона,
убедившись, что прежний worker и его дочерний процесс завершены. Повторный `init`
не нужен: принятые стадии и проверенный кэш переиспользуются.
Не удаляйте кэш и не обходите проверки. Изменился исходник —
создайте новое задание. Входные книги и прежние готовые PDF не изменяются.
Читателю достаточно PDF; для продолжения работы сохраните всю папку задания.

## 8. Запуск через недорогого агента

Откройте папку скилла в OpenCode или другом агенте с терминалом и файлами.
Управляющая модель может быть дешёвой/локальной; отдельная платная подписка
для самого конвейера не нужна. Пример:

> Прочитай SKILL.md в этой папке. Переведи книги из D:\Books в новое задание
> D:\Translations\batch-01. Работай локально, без облака и полировки.
> Сначала проверь окружение и настройки модели. Сам книгу не переводи:
> используй pipeline.py init, plan, run, status. Исходники не менять.
> Если чего-то не хватает, сообщи причину; не обходи проверки.

Полный [промпт](ПРОМПТ.md). Остальные 26 скиллов — дополнительные экспертные
инструменты, не зависимости архива: [пояснение](ЧИТАТЬ_ПЕРВЫМ.md).

## Linux/macOS и офлайн

Уровень проверки этого выпуска: новая распаковка ZIP и новый venv на Windows,
пакеты заново установлены из PyPI, пользовательские Python-пакеты отключены,
PATH очищен. Полноценная новая Windows/VM здесь не использовалась; установку
самих Python, Pandoc, MiKTeX, LM Studio, GPU-драйверов и загрузку моделей с нуля
эта проверка не подтверждает. При интеграциях использованы имеющиеся Pandoc/TeX
и синтетические ответы локального тестового HTTP-сервера, не настоящая MT-модель.

Отдельно после установочной проверки выполнен настоящий цикл MinerU → Hy-MT2
→ PDF на синтетическом двухстраничном документе. Использованы уже установленные
CUDA-зависимости и веса; проверка не была новой установкой GPU-окружения.
Результаты, исправления и смысловые ограничения — [docs/VALIDATION.md](docs/VALIDATION.md).

Установщик пропускает неисправный Python-кандидат и ищет следующий. Сообщение
версии в stderr само по себе не ошибка; проверяется также код завершения.
`psutil` обязателен для диспетчера. Доктор не принимает ненулевой код TeX,
нечитаемый PDF или пропавшую кириллицу за успешную установку.

Полный новый установочный прогон на этих ОС не подтверждён. Базовый порядок:
`python3 -m venv venv`, `venv/bin/python -m pip install -r requirements.txt`;
Pandoc/TeX/сервер/OCR ставятся отдельно, `psutil` обязателен для процессов.
В командах замените Windows-интерпретатор на `venv/bin/python` и пути на свои.

Первая установка требует интернета. Для офлайна заранее скачайте MT/OCR-веса
и TeX-пакеты. По умолчанию перевод идёт только на loopback-сервер; это не сетевой
экран. Если управляющий агент облачный, сведения, которые вы ему передаёте,
могут уйти в его сервис. Для полного офлайна нужен локальный агент или команды
без агента. Конвейер не гарантирует полноту OCR и смысловую точность перевода.

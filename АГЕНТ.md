# АГЕНТ.md — карта конвейера для ИИ-агента

Обычный запуск теперь через `scripts/pipeline.py`: `init INPUT --out NEW_JOB`,
`plan JOB`, `run JOB`, `status JOB`. Агент только диспетчер; всё локально,
полировка/автоглоссарий/облако по умолчанию выключены.
Начни с короткого `SKILL.md` и [LOCAL_AGENT](docs/LOCAL_AGENT.md).
Долгий запуск на Windows: `start JOB`, затем `background-status JOB`;
отмена — `stop JOB`. Владение процессами и LM Studio, журналы и границы
устойчивости описаны в [BACKGROUND_RUN](docs/BACKGROUND_RUN.md).
Этот большой файл — справочник ручных стадий и диагностики, не обязательный
контекст каждого запуска. Список скриптов также в `PIPELINE_REFERENCE.md`.

Прочитал этот файл — можешь работать, не анализируя исходники. Здесь: что это,
как выбрать режим, все файлы, форматы артефактов, приёмка, типовые поломки.

Перед ручным запуском стадий/правкой отчётов прочитай [контракт целостности](docs/INTEGRITY.md):
новый кэш, манифесты частей, цепочки постправок, профили приёмки и публикация
через отдельного кандидата. Результаты переноса опыта тома 6 —
отчёт (`docs/опыт-тома-6/04_РЕЗУЛЬТАТ.md`, только в полной версии). Эти правила уточняют прежние
примеры ручной сборки ниже: наличие PDF или код 0 отдельной команды не равны выпуску.

После реального пилота Luna добавлены ранние проверенные OCR-правки,
границы прибавлений, точные алиасы дублей заголовков и два независимых
контроля: `ocr_review` до MT, `term_guards` после MT и перед выпуском.
Форматы и коды остановки — в контракте; результат пилота (`docs/опыт-тома-6/05_ПРОВЕРКА_LUNA.md`, только в полной версии).
Книжные термины и поправки по сканам хранятся в профиле, не в общем скрипте.
Для сложного OCR прочитай раздел «Защиты после сложного пилота» в контракте:
`unit_anchors` сохраняет границы и типы примечаний, страницы показываются
охватом блока; новые многоточия и неразобранные замечания агента блокируют выпуск.
Не принимай технический `passed` за завершённую смысловую вычитку.

## Что это

Локальный конвейер «английская книга → русский PDF через LaTeX». Прозу переводит
локальная MT-модель (Hy-MT2-7B в LM Studio, порт 1234); математика, код, команды
и URL **маскируются до перевода** плейсхолдерами `⟦M######⟧` и восстанавливаются
после по карте. Проверяется сохранность масок, но полнота исходного OCR требует сверки. Всё работает
офлайн; ничего не уходит во внешние сервисы.

## Роутер: какая задача → что запускать

| Ситуация | Действие |
|---|---|
| Папка с книгами (pdf/epub/fb2/docx/…), вёрстки нет | `python scripts\translate_book.py <книга>` (одна) или `scripts\translate_folder.py <папка>` (все) — делают всё сами |
| У проекта **свой** LaTeX-каркас с маркерами вставки | `python skeleton\translate_into_skeleton.py <проект> --offset N` — оркестраторы выше запрещены (построят параллельную книгу) |
| Прогон прервался / упал | Повторить ту же команду — извлечение пропустится, перевод продолжится с кэша |
| Готов только перевод, нет PDF | Войти на стадии LaTeX/сборки (стадии 5–7 ниже) |
| Пришёл готовый промпт-задание | Читай `ПРОМПТ.md` — там готовый регламент обоих режимов |
| Нет GPU / нужен другой движок / полировка / бюджетные требования | **Читай `КОНФИГУРАЦИИ.md`** — каталог сборок: движки К1–К7, слои полировки П0–П3, агенты-операторы |

Подробный регламент стадий — `SKILL.md`; человеческие руководства —
`README.md`, `РУКОВОДСТВО.md`, `ПОСОБИЕ.md`. Старый `ПОСОБИЕ.pdf` не отражает новую приёмку.

## Окружение (важно!)

- **venv обязателен**: MinerU/Marker/PyMuPDF стоят в `venv\` этой папки, НЕ в
  системном Python. Перед любой работой:
  ```powershell
  $env:PATH = "$PWD\venv\Scripts;$env:PATH"   # из корня конвейера
  $PY = "$PWD\venv\Scripts\python.exe"
  ```
  Иначе преflight упадёт с «'mineru' not found in PATH».
- **LM Studio**: сервер на `http://localhost:1234` (Developer → Start Server).
  Модель `hy-mt2-7b` грузить заранее не нужно — JIT-подгрузка при первом
  запросе; преflight требует только живой сервер. Сэмплер при загрузке:
  temp 0.7, top_p 0.6, top_k 20, repeat 1.05, контекст 8192.
- **GPU — железное правило: перед КАЖДЫМ извлечением MinerU/Marker LLM
  выгружается.** Внутри одной книги это происходит само (модель ещё не
  загружена, JIT подхватит её после извлечения). Но в очереди книг/глав
  модель остаётся в памяти от перевода предыдущей — MinerU уходит в
  thrashing вплоть до зависания системы; `--vram-limit` это НЕ лечит. Оба
  оркестратора с 2026-07-12 выгружают модель сами (`lms unload --all`
  перед извлечением). При ручных стадиях выгружайте сами: Eject в LM Studio
  или `%USERPROFILE%\.lmstudio\bin\lms.exe unload --all`.
  Правило касается ТОЛЬКО GPU-извлекателей (MinerU, Marker, vision-проходы).
  OCR фрактурного маршрута — Tesseract, он работает на CPU и видеопамять
  не занимает вовсе: выгружать модель перед ним не нужно (проверено
  07.08.2026 — 393 стр. за 5 мин при резидентной hy-mt2, без деградации).
- `.sh`-скрипты запускаются через Git Bash; TeX — MiKTeX (xelatex + latexmk).
- Ollama (`--mode generic`, порт 11434) — запасной/полирующий движок.
- **Глобальный замок конвейера**: GPU один, поэтому оркестраторы и
  `extract_chunked.py` берут один замок на машину
  (`%TEMP%\freetranslate.lock`). Второй прогон честно ждёт первого
  («жду замок конвейера…») — это штатная очередь, не зависание. Держатель
  обновляет mtime замка каждые 60 с; замок погибшего прогона снимается сам
  через 10 мин. Снять руками: удалить файл. Обойти (осознанно): `--no-lock`.
  Дочерние процессы держателя проходят без ожидания (env `FREETRANSLATE_LOCK`).
- **Таймаут MinerU**: VLM MinerU стохастически виснет в генерации (часами).
  Все вызовы идут через `procutils.run_mineru` с таймаутом (`--mineru-timeout`,
  по умолчанию 3600 с на чанк, 1800 с на главу skeleton): по истечении дерево
  процессов убивается, код возврата 124. Зависание стохастическое — повторный
  запуск той же команды безопасен и обычно проходит (в `extract_chunked` один
  авторетрай чанка встроен).

## Работа из агентской сессии

Отдельный режим эксплуатации: конвейер запускает не человек у терминала, а
агент, у которого свои ограничения.

- **Потолок одного вызова инструмента.** На толстой книге вызов был убит
  инфраструктурой примерно на 50-й минуте (наружу это всплыло как
  `ChildProcess.kill`), и запрошенный timeout не помог. Поэтому стадии
  нарезаются так, чтобы каждая укладывалась в вызов с запасом: извлечение
  чанками **≤50 страниц** (~4 мин MinerU при `--vram-limit 8`), перевод
  частями **≤300 блоков** (6–13 мин при `--parallel 3`).
- **Отсоединённые процессы — проверять, а не верить.** На сеансе NFCM
  `Start-Process -WindowStyle Hidden` погибал вместе с концом вызова; на
  сеансе фрактурных томов такой процесс границу вызова пережил и доработал
  сам. Среда исполнения бывает разной, и на кону часы. Минутный опыт перед
  длинной стадией: запустить скрипт, который раз в 3 с дописывает тик в
  файл, и в следующем вызове посмотреть, растёт ли файл.
- **Что бы ни решилось про фон — стадии должны быть возобновляемыми.** Это
  главное. У переводчика кэш блоков, у извлечения — готовые чанки, у
  сборки — `body.tex`. Повтор той же команды продолжает с места обрыва, и
  тогда гибель процесса стоит минут, а не прогона.
- **Не редактировать `scripts/` во время прогона книги.** Работающий
  процесс свой код уже загрузил, но подпроцессы (`translate.py` на каждую
  часть, `extract_chunked` на каждый чанк) подхватят новую версию — и часть
  книги уедет по другим правилам. Правки книги живут в её артефактах.
- **Никакого инлайн-кода с кириллицей через пайп PowerShell** (`$code | &
  python -`): литералы приезжают в cp866. Только файловые скрипты в UTF-8.

## Оркестраторы

**`scripts/translate_book.py <вход>`** — одна книга целиком: конвертация/
извлечение → санация → маска → перевод → размаскирование → LaTeX → умная
сборка XeLaTeX (до стабилизации aux+toc, ≤4 прохода) → верификаторы.
Вход: pdf (`--extract auto|digital|scan|math`), epub/fb2/docx/odt/html/rst
(pandoc напрямую), txt/md (как есть), djvu/mobi/azw (через Calibre).
Флаги: `--glossary Ф | --auto-glossary [--review-glossary]`, `--workdir`,
`--parallel N`, `--vram-limit ГБ`, `--pages-per-chunk N` (math-PDF > 200 стр.
извлекается частями — обход 60-мин таймаута MinerU), `--force`, `--no-clean`,
`--layout screen|print|compact`, `--title/--author`, `--heading-numbers
auto|latex`, `--mode hymt|generic`, `--model`, `--host`, `--target-lang`,
`--mineru-timeout С`, `--no-lock`, `--polish [--polish-model M --polish-host H]`
(стадия 4b: литературная полировка перевода вторым проходом — маска → 
`translate.py --mode polish` → размаскирование; по умолчанию Ollama :11434 /
qwen3.5:9b; слои полировки — `КОНФИГУРАЦИИ.md`).
Результат: `<книга>_ru\<книга>.ru.pdf`. Повторный запуск = возобновление.

**`scripts/translate_folder.py <папка>`** — очередь книг, обёртка над первым:
ошибка одной не валит остальные, готовые пропускаются, PDF дублируются в
корень `_translated\`. Флаги: `-r`, `--outdir`, `--force` + сквозные выше
(включая `--polish`, `--mineru-timeout`, `--no-lock`).

**`skeleton/translate_into_skeleton.py <проект>`** — те же стадии, но перевод
раскладывается по маркерам чужого каркаса, сборка родным движком проекта
(LuaLaTeX/XeLaTeX — автодетект). Каждая глава находится в PDF **сама** по
печатным номерам страниц (`--folio auto`, по умолчанию), поэтому `--offset N`
не обязателен — он лишь запасной вход для сканов без текстового слоя и
перекрёстная проверка. Сначала `--dry-run` (печатает найденные pdf-диапазоны
и фактический офсет каждой главы). После успешной сборки сам запускает
`layout_report.py` (метрики, overfull, превью — в `book\preview\`).
Подробности: `skeleton/README.md`.

## Стадии вручную (отладка; артефакт каждой — вход следующей)

```bash
# 1. Извлечение: PDF -> markdown (+картинки).  режимы: auto|digital|scan|math
bash scripts/extract.sh book.pdf out/ math          # -> out/book/book.md
# 1a. Санация OCR-мусора (идемпотентна; выключатели --no-strip-toc и т.п.)
python scripts/clean_markdown.py out/book/book.md out/book/book.clean.md
# 2. Маскирование математики/кода/URL
python scripts/mask_math.py mask out/book/book.clean.md work/book.masked.md work/book.map.json
# 3. Перевод (возобновляемый; кэш .tcache; --cache-dir задаёт явно)
python scripts/translate.py work/book.masked.md work/book.ru.masked.md \
    --mode hymt --model hy-mt2-7b --host http://localhost:1234 --glossary glossary.md
# 4. Размаскирование + починка битых токенов по карте
python scripts/mask_math.py unmask work/book.ru.masked.md work/book.ru.md work/book.map.json
#    в логе: restored exact/repaired damaged/unresolved — unresolved ДОЛЖЕН быть 0
# 5. markdown -> LaTeX (преамбула + lua-фильтры figcaption/structure)
bash scripts/to_latex.sh work/book.ru.md build/ assets/preamble.tex
# 6. Сборка
bash scripts/build.sh build/                        # -> build/main.pdf
# 7. Ошибки: читать build/main.log; чаще всего неэкранированный % & _ # $ { }
#    в прозе -> экранировать в build/body.tex, пересобрать, повторять до чистой
```

## Форматы и артефакты

- **Рабочая папка книги** `<книга>_ru\`: `extract\` (md + картинки),
  `work\` (masked/ru.masked/ru.md, map.json, glossary.md, кэш `.tcache\`),
  `build\` (main.tex, body.tex, main.pdf, main.log, отчёты верификаторов).
- **Плейсхолдер** `⟦M######⟧`; карта id→оригинал — `*.map.json`. Битые скобки
  (`⟨M001705⟩` и т.п.) чинятся на unmask; переводчик отбраковывает и не кэширует
  ответы с повреждёнными токенами.
- **Глоссарий**: строки `en => ru` (`glossary.example.md` — образец;
  `scripts/make_glossary.py` строит автоматически — работает и с облачным
  эндпоинтом через `$env:LLM_API_KEY`). Держать компактным (< ~100 строк;
  иначе маленькая модель теряет инструкции). Если в проекте есть
  `glossary.tsv` + генератор — источник истины TSV, md регенерируется.
  Мастер-глоссарий разросся — тонкий фид на главу строит
  `scripts/slim_glossary.py` (всегда-классы по пометке в note + строки «гл.N»,
  потолок `--max-rules 100`); мастер остаётся для аудита.
- **Санация** пишет вырезанное в `.removed_*.md` (аудит); `.clean.md` —
  производный файл, его нельзя брать как исходник повторно.

## Приёмка (что проверить перед «готово»)

1. Итоговый PDF существует и открывается; число страниц правдоподобно.
2. `unresolved: 0` в логе размаскирования (иначе потеряны формулы) — с
   2026-07-15 это жёсткий гейт в ОБОИХ оркестраторах, не только в skeleton.
3. `kept_source: 0` в `<dst>.report.json` рядом с переводом (иначе часть
   блоков осталась английским исходником; код возврата 4).
4. `audit_selfcheck.py` — пропуски в нумерации формул/утверждений (с номерами
   строк md), рисунки: подписи vs упоминания, нумерация разделов, повторы
   заголовков (дубли извлечения), гигиена PDF-текста. `layout_report.py` — метрики, топ overfull со страницами,
   пропавшие глифы, превью страниц. Оркестратор запускает оба сам; отчёты — в
   `build\`. Глубокий аудит вёрстки: `full_audit.py` (m1–m8, PNG-доказательства).

## Типовые поломки → лечение

| Симптом | Причина/лечение |
|---|---|
| `'mineru' not found in PATH` | venv не в PATH — см. «Окружение» |
| Сервер молчит на :1234 | Попросить пользователя: LM Studio → Developer → Start Server |
| `unresolved: N` > 0 | Перезапустить перевод (битые ответы не кэшируются); если упорно — искать токен в ru.masked.md руками |
| `! Undefined control sequence` и т.п. в main.log | Спецсимвол в прозе → экранировать в body.tex (стадия 7) |
| `Undefined control sequence` на `\square`/`\Box` (unicode-math без легаси-имён) | `\providecommand{\Box}` НЕ срабатывает (ядро LaTeX уже определяет `\Box` заглушкой-ошибкой). Лечение: `\providecommand{\square}{\mathord{^^^^25a1}}` в преамбуле + замена `\Box`→`\square` в теле |
| MinerU молчит > 60 мин | Большой PDF: `--pages-per-chunk` (по умолчанию 200) уже включён у оркестратора; вручную — `scripts/extract_chunked.py` |
| Извлечение оборвалось с кодом 124 | Таймаут `run_mineru`: VLM завис в генерации (стохастически). Перезапустить ту же команду — обычно проходит; для плотных PDF поднять `--mineru-timeout` |
| У глав отрезаны последние страницы (пропали «Основные определения главы» и т.п.); folio не совпадает | Дрейф офсета: единый `--offset` неверен для части книги (нумерованные, но не считаемые страницы-разделители). `--folio auto` (по умолчанию) находит каждую главу сама; при несовпадении нарезки конвейер её бракует. Проверить: `--dry-run` печатает фактический офсет по главам |
| `translate.py` вернул код 4 / `!! непереведённых блоков` | Часть блоков не перевелась и осталась исходником. Оркестраторы делают один авторетрай сами (провалы не кэшируются); ГОРСТЬ (≤2 или ≤2% — обычно имена/библиография) допускается и конвейер идёт дальше к PDF, массовый недобор бракует. Список — в `<dst>.report.json` (`kept_source`, `failed_blocks`); порог: `--untranslated-tol` |
| hy-mt2-7b начал возвращать английский (echo) после ~350 блоков длинной книги | Модель «устаёт» на длинной сессии. Эхо-валидатор бракует, но recovery нет: разбить masked-файл на части по ~300 блоков и перевести каждую своим `--cache-dir`, затем слить (translate.py подскажет это в сообщении об echo) |
| `--extract digital`: в PDF нет картинок / «текст» из кракозябр | pymupdf4llm извлекает растровые картинки (`write_images`), но НЕ рендерит векторную графику — её «текст» = OCR-мусор (снимается `strip-ocr-garbage`). Для книг с рисунками/формулами брать `--extract auto` (Marker) или `math` (MinerU); digital предупреждает об этом сам |
| generic-режим: модель галлюцинирует (случайный текст, ~1% кириллицы) | Не-instruction модель (напр. gemma-*-obliterated) не держит промпт. translate.py предупреждает, если модель вне белого списка; брать qwen3.5/deepseek |
| plane-1 математика (𝜃/𝜅) стала хангылем (훃/휙) | pymupdf4llm потерял старший байт (U+1D703→U+D703). Санация восстанавливает диапазон 0xD400–0xD7FF (+0x10000 → plane-1 → `$\theta$`) |
| В тексте `$10 billion` замаскировался как формула, абзац не переведён | Разэкранирование `\$…\$` цепляло валюту. Исправлено: `_dollar` не трогает `\$` перед цифрой и длинную прозу (санация) |

## Плашки-определения, уехавшие картинками (vision-rescue)

MinerU превращает затенённые выносные рамки (Definition of… / N-th Postulate /
Principle of…) в картинки — их текст никогда не переводится. **Пере-OCR кропов
самим MinerU НЕЛЬЗЯ**: его VLM стохастически виснет на них в генерации (часами).
Восстановление — зрением агента, три шага:

1. **detect** (делает конвейер сам): `rescue_plaques.py detect <md> --json cand.json
   --report r.md` — находит кропы-кандидаты (широкие-низкие, без подписи), пишет
   их список **и готовый промпт для vision-агента** (`plaques_vision_prompt.md`
   рядом с отчётом — самодостаточный: пути кропов, правила классификации,
   формат JSON, команда патча). Быстро, без GPU.
2. **vision** (агент): передай `plaques_vision_prompt.md` субагенту verbatim
   (или выполни сам): открой каждый кроп `Read`'ом, классифицируй
   `plaque|figure|formula|text|other`; для `plaque` — переведи в `title_ru` +
   `body_ru` (готовый LaTeX, математика в `$…$`). Запиши JSON-массив
   `{hash,kind,title_ru,body_ru}` (по файлу на главу; для большой книги раздай
   главы субагентам). Настоящих плашек обычно единицы на главу — остальное
   формулы/рисунки, оставь картинками.
3. **patch**: `rescue_plaques.py patch <vision.json> <chapter.tex>` (или
   `patch-dir <vision_dir> <chapters_dir>`) — вставит бокс плашки по хэшу картинки
   и снимет дубль-заголовок, который MinerU выдал отдельной секцией. Затем пересборка.

## Зоопарк MinerU: что приезжает в математике

Разобрано на «New Foundations for Classical Mechanics» (718 стр. плотной
геометрической алгебры). Первые шесть строк конвейер чинит сам —
`clean_markdown.py`, секция repair-math; остальное правится по месту.

| Класс | Пример | Лечение |
|---|---|---|
| переключатель шрифта + мат. акцент | `{\bf \dot{\theta}}^2` | **авто** → `\boldsymbol{\dot{\theta}}`; роняет XeTeX, см. таблицу поломок |
| overset на отношении | `\overset{△}{<}` | **авто** → оставить отношение |
| overset-мусор | `\overset{\cdot}{\ }`, `\overset{\cdot}{8}` | **авто** → тело; тело-буква → `\dot{тело}` |
| `\textbf{\em X}` обеих форм | жирный курсив | **авто** → `\boldsymbol{X}` |
| `\mathsf{\bar{(2.16)}}` | номер уравнения под баром | **авто** → `(2.16)` |
| `\mathbf{\overset\ddots}` | матричные точки | **авто** → `\ddots` |
| строчные в `\mathscr{}` | у rsfs нет строчных глифов | **авто** → `\mathit{…}` |
| башня overset (~15 уровней) | абзац о собственных векторах | руками: `e_\parallel`, `e_\perp` |
| `\llangle`, `\overrightharpoon` | не определены | убрать или заменить по смыслу |
| литеральные `\$…\$` в подписях | `\lambda_1 =$3/2.$` | починить формулу подписи руками |
| строки «пустых страниц» | `7KLVSDJH…` (битый ROT) | удалить строку |
| OCR-обломки абзацев | `(7.1) d u ù u u²ú …` | удалить абзац |
| разреженный английский в формуле | `\mathrm{- v e c t o r}` | перевести и склеить |

Эталонные регэкспы массовых правок — в `apply_all_fixes.py` (корень).
Осторожно: любой глобальный регэксп по прозе обязан иметь **кириллический
страж**, иначе ложная пара `$…$` вклеит русский текст внутрь математики.

## Запреты

- **Не править** `scripts/` и `assets/` под конкретную книгу — чинить только
  файлы книги (markdown, body.tex). Улучшения конвейера — отдельная задача.
- **Не редактировать глоссарий во время прогона** — правка сбрасывает кэш
  перевода книги.
- **Не запускать** `translate_book.py`/`to_latex.sh`/`build.sh` в проекте с
  собственным каркасом — только `skeleton/`-оркестратор или ручные стадии 1–4.
- **Не брать** `.clean.md`/`.removed_*.md` за исходный markdown.
- Ручные правки сгенерированных `.tex` недолговечны: `build/body.tex` живёт до
  следующей стадии 5, `chapters/*.tex` в skeleton-режиме стирает перегенерация
  главы (`--force`). Долговечные правки — в markdown (`work/book.ru.md`) или
  в санацию.

# Явные решения для конкретной книги

`translate_book.py --book-profile FILE.json` применяет профиль schema 1.
В диспетчере `pipeline init --settings FILE` поле `book_profile` задаёт путь:
файл копируется в input snapshot одного книжного задания. Для пакета книг
решения готовят отдельно: номера и хэши одной книги не применяются к другой.
Профиль глоссария `glossary_profile` — отдельная настройка выбора терминов,
она поддерживается во всех маршрутах.

Без профиля очистка сохраняет содержимое. Реестр `work/cleaning.coverage.json`
содержит упорядоченные объекты Markdown, хэши и диапазоны до/после. Это контроль
преобразования уже извлечённого Markdown; полноту OCR относительно PDF он не
доказывает. Прежняя `clean_text` остаётся низкоуровневой библиотекой исторических
эвристик для явного исследовательского использования, штатный CLI её не вызывает.

Все SHA-256 вычисляются по точному UTF-8 содержимому, включая переводы строк.
Диапазоны `start`/`end` — позиции символов Python (end не включается), не байты.
Причина и уникальный `id` обязательны; устаревший хэш или неоднозначное совпадение
останавливают стадию. Не меняйте хэши старого отчёта ради принятия новых данных.

Для точного участка очищаемого исходника:

```json
{
  "schema": 1,
  "cleaning": {
    "source_sha256": "SHA256_ВСЕГО_ИСХОДНОГО_MARKDOWN",
    "decisions": [
      {
        "id": "printed-toc",
        "start": 0,
        "end": 123,
        "source_sha256": "SHA256_ТОЧНОГО_УЧАСТКА",
        "action": "rebuild",
        "reason": "Сверено с оригиналом: печатное оглавление заменяется оглавлением XeLaTeX"
      }
    ]
  }
}
```

Это схема с заполнителями, не готовый профиль. `keep` сохраняет участок,
`omit` явно исключает его с сохранением текста в отчёте. `rebuild` разрешён
только для однозначно распознанного оглавления с номерами страниц; выпуск требует
сгенерированного TOC. Указатель не считается оглавлением. Неуказанные участки
сохраняются. Удаления сносок/таблиц могут дополнительно блокироваться структурными
проверками: профиль не отключает остальные проверки.

Правка после перевода задаётся отдельно, например исправление проверенного
OCR-заголовка. В общий код имена авторов и названия конкретной книги не добавляются:

```json
{
  "schema": 1,
  "post_edits": [
    {
      "id": "cover-title",
      "source_sha256": "SHA256_ТОЧНОГО_book.ru.md",
      "old": "# Акупунктура 0",
      "new": "# Атлас акупунктуры",
      "expected_matches": 1,
      "reason": "Заголовок сверен с титульной страницей конкретного издания"
    }
  ]
}
```

`old` должен встретиться ровно один раз; для коротких/повторных названий включите
соседний контекст. Все правки привязаны к одному исходному тексту, не цепочкой.
Сырой `work/book.ru.md` сохраняется; результат — `work/book.ru.reviewed.md`,
доказательства — `work/postprocess.coverage.json`. Release связывает хэши профиля
и обоих отчётов. Неизвестные управляющие символы требуют сверки исходника или
точной подтверждённой замены; безусловного удаления больше нет.

`--no-clean` не может пропустить заданные cleaning.decisions. `--keep-source`
несовместим с post_edits: пока перенос диапазонов через unmask не реализован,
правки требуют отдельной проверенной редакции источника. Готовые книги не служат
изменяемым испытательным материалом; используйте новый каталог задания.

# Недорогой агент управляет локальным конвейером

Задача агента — запуск, короткий статус и разбор конкретной ошибки. Извлечение,
перевод, повторы запросов, кэш и вёрстка выполняются скриптами. Управляющий агент
может быть локальным или доступным в OpenCode/другом клиенте; конвейер не зависит
от его подписки/модели. После запуска агент может вообще не понадобиться.

## Быстрый запуск

Из корня конвейера, PowerShell; `INPUT` — файл/папка, `JOB` — новая папка:

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py init "INPUT" --out "JOB"
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py plan "JOB"
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py run "JOB"
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py status "JOB"
```

Умолчания: OpenAI-совместимый сервер `http://localhost:1234`, `hy-mt2-7b`,
`hymt`, один запрос одновременно. Полировка, облако, автоглоссарий и научная
вычитка **не запускаются**. `glossary.md` рядом с книгой используется, если есть.
При наличии только `glossary.tsv` сначала подготовить Markdown книжным генератором.

Для новой технической книги предложите отдельную подготовку и проверку
терминологии, но не запускайте её скрыто. Готовый `glossary.md` должен лежать
рядом с книгой (для skeleton/OCR — в корне проекта) **до `init`**. При пакетном
запуске общий файл используется для всех книг этой папки; разные словари —
отдельные задания. После изменения словаря нужен новый вход/новое задание,
а не правка зафиксированного `JOB/input`. Рецепт, задание ассистенту и ограничения
автогенератора: [глоссарий в README](../README.md#глоссарий-подготовить-один-раз-использовать-во-всей-книге).

`init` копирует вход в `JOB/input`, фиксирует хэши и создаёт `pipeline.job.json`.
Существующий выходной каталог не принимается. Исходная папка и готовые PDF
не перезаписываются. Список книг очереди зафиксирован при создании задания.

## Автоматический выбор маршрута

| Вход | Действие |
|---|---|
| Один поддерживаемый файл | `translate_book.py`, отдельный workdir |
| Папка книг | Последовательные `translate_book.py` |
| `pages/` + `structure.json` | Копия OCR-проекта → `build_ocr_md` → `run_doc_translate` → `assemble_ru_book` |
| `book/main.tex` либо `main.tex`, один исходный PDF в корне | Копия проекта → skeleton-оркестратор |

Markdown/TXT/RST/HTML передавать отдельным файлом: пакетный поиск не должен
принимать README, глоссарий или лог за книгу. `*.ru.pdf` пропускается, подпапки
автоматически не обходятся. К одиночной книге копируется `images/`; нестандартные
внешние ресурсы сначала собрать в самодостаточный вход. Для skeleton сохраняется
структура проекта, но не старые build, `_skeleton_work`, кэши и служебные каталоги.
Использовать только доверенный TeX-каркас: рабочая копия — не системная песочница.

Нераспознанная фрактура требует OCR/структуры по `PIPELINE_REFERENCE.md`;
диспетчер не угадывает шрифт по имени PDF. OCR по умолчанию German→Russian;
books/skeleton — English→Russian. Другие языки для последних требуют расширенного
маршрута, а не тихого игнорирования настроек.

## Другой движок

Файл `local-model.json`, передаваемый в `init --settings local-model.json`:

```json
{"host":"http://127.0.0.1:8080", "model":"EXACT_SERVER_MODEL_ID", "mode":"generic", "parallel":1}
```

ID взять из `/v1/models`, не угадывать. В локальном режиме `LLM_API_KEY` удаляется
из окружения дочерних стадий. Для удалённого/LAN адреса нужны явный выбор пользователя
и `allow_remote: true`; ключ только через окружение. Автоперехода в облако нет.
Loopback-проверка охватывает модельные HTTP-запросы и редиректы, но это не firewall:
для офлайна заранее установить веса OCR/MT и TeX-пакеты. Новые модели не скачиваются
диспетчером. Существующий посторонний GPU-сервер нельзя убивать как «зомби».

Настройки: `extract` (auto/digital/scan/math), `mineru_timeout` (3600 с),
`timeout` (86400 с на стадию), OCR `parts` (100 блоков), `split_chars` (900 знаков),
`context_per_request` (0 = неизвестен), `title`, `author`. Неверные/неизвестные поля
отвергаются. `polish: true` требует явного расширенного workflow, не запускает
скрытую стадию. Смена настроек инвалидирует готовность. На новой версии кода
извлечение может потребовать нового задания; не добавлять `--force` автоматически.
Входной snapshot неизменяем: книжные правки — новый вход и новое задание.

## Статус и восстановление

`pipeline.status.json` обновляется атомарно каждые 5 секунд во время стадии.
CLI `status` выдаёт компактный JSON без текста книги: стадия, готовые/все стадии,
время, размер лога, результат и следующее действие. Это **не** процент перевода/ETA.
Не читать весь лог в модель каждые несколько секунд. `run` работает в foreground.
На Windows для долгого запуска: `start JOB`, затем `background-status JOB`.
Однократная задача Планировщика от текущего пользователя отделяет конвейер от
консоли отправителя. `stop JOB` отменяет свой запуск; повторов по расписанию нет.
Подробности запуска LM Studio и границ устойчивости — [BACKGROUND_RUN.md](BACKGROUND_RUN.md).

| Статус | Действие |
|---|---|
| ready | `run JOB` |
| running | ждать, не запускать второй экземпляр |
| done | показать пути PDF; приёмка только техническая |
| interrupted | повторить `run`, если дочернего процесса нет |
| needs_attention | прочитать указанный лог/отчёт и исправить причину |
| stale | проверить изменение файлов/настроек/кода; повторить или создать новое задание |

Живой осиротевший ребёнок запрещает повторный запуск. Таймаут останавливает
своё дерево; кэш сохраняется. При занятом глобальном замке — отказ, не бесконечная
очередь. Повторы запросов ограничены переводчиком; всю книгу бесконечно не повторяем.
После серверного exit 3 OCR-очередь не тратит тот же бюджет ошибок на остальные части.
Успешные стадии не запускаются вновь при совпадении настроек, кода и выходных хэшей.
После неполного MT повтор использует проверенный кэш. Для `done` недостаточно exit 0:
нужен PDF с согласованным `.release.json`. Старый PDF не считать новым результатом.

## Приёмка без обязательной дорогой вычитки

В маршруте MinerU сохраняйте `_content_list.json` рядом с сырым Markdown.
`prepare_mineru.py` восстанавливает однозначные сноски и простые таблицы перед MT;
`.prepare.json` объясняет отказ при неоднозначности. Детали/границы поддержки —
[INTEGRITY.md](INTEGRITY.md). При остановке нельзя просто пропустить этот этап.

Маски, структура, идентичность частей и сборка проверяются всегда.
Дополнительно сравниваются цифровые группы, метки перечислений и ID сносок;
это дешёвая проверка известных классов потерь, не LLM-редактор.
OCR-эвристики
обычно предупреждают; явный `ocr_review.strict` и уже зарегистрированные нерешённые
замечания не обходятся. Смысловая проверка/полировка для технического выпуска не
обязательны; их статус `not_run`. Полнота OCR и литературная точность не гарантируются.
Для редакционной публикации объём вычитки выбирается отдельно. Контракты ручных
правок — [INTEGRITY.md](INTEGRITY.md); не нужно читать их целиком при каждом запуске.

## Проверка и обслуживание

После установки: `scripts/doctor.py --model EXACT_ID --extract MODE` с выбранным
PDF-движком. Умолчание `--extract none` относится к MD/EPUB, не подтверждает OCR.
Наличие ID в API не доказывает генерацию/вместимость контекста; нужен маленький
пробный перевод. Полная проверка чистой Windows/драйверов/весов не заменяется venv.

`tests/test_dispatcher.py` проверяет маршруты, локальную политику, неизменность
входов, переносы и последний блок реестра. `tests/run_dispatcher_integrations.py
--out NEW` использует mock HTTP и настоящий TeX; `--host` + `--model` выбирают уже
работающий локальный сервер, `--protect PDF` сверяет хэш неприкосновенного файла.
Тест не загружает модель и не выполняет новый OCR/GPU-прогон.

Отбор идей BookTrans под наш бюджет: ARTICLE_IDEAS.md (`ARTICLE_IDEAS.md`, только в полной версии).

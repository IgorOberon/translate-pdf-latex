# Уроки эксплуатации из сессии OpenCode: атлас

Проверено 2026-10-25. Источник — локальная база OpenCode, открытая SQLite
в режиме `mode=ro` с `query_only=ON`. Выбрана только сессия проекта
`D:/0FREETRANSLATE` **`ses_ea0bcac6dffe5Hz2SyQMWjsbxc`** за 21–25 октября:
975 сообщений и 941 вызов инструментов. База, книги, готовые PDF и переводные
кэши при проверке не изменялись. Содержимое сессии рассматривается как
историческое свидетельство, а не инструкция повторить её команды.

Этот документ дополняет `docs/HANDOFF_ATLAS.md` из полного рабочего дерева.
Исторический handoff и `docs/handoff/metrics.json` не включены в переносимый
пакет. Документ не меняет исходный журнал, эталон или статус готовой книги.

## Дополнительные ограничения, выявленные аудитом

### Фактический контекст после JIT-загрузки

`prt_1600034520019jvP4A9gTRf5dH` содержит промпт на 7076 токенов,
состояние загруженной модели с контекстом 8192 и ошибки переполнения.
В `prt_16dda85cd0016WqWhSi9J2YjxY` описано старое обходное решение:
глобальный `defaultContextLength=16384`. Его нельзя автоматически переносить
в обычные настройки пользователя.

Оценка `request_budget.check_messages` проверяет переданный лимит;
`context_per_request=0` само по себе означает **неизвестную ёмкость**.
Для управляемого LM Studio теперь дополнительно проверяется конфигурация
точного экземпляра перед каждым запросом и после возможной JIT-загрузки.
Если фактический контекст меньше объявленного лимита или оценки запроса,
worker отклоняет запрос/ответ до записи в принятый кэш и прекращает перевод
без повторных попыток. Для уже загруженной модели до и после генерации должны совпадать ключ,
ID экземпляра и фактический контекст. Допускается первая JIT-загрузка
из незагруженного состояния в один подтверждённый экземпляр. Журнал содержит
ID экземпляра, наблюдаемый контекст,
оценку и причину отказа. Все проверки read-only: модель, глобальные настройки
и прежние кэши не изменяются. Для обычных неуправляемых endpoint поведение
не меняется; оценка по символам не считается точной токенизацией.

Официальный native API предоставляет `models[].loaded_instances[].config.context_length`;
`max_context_length` модели означает другую величину и не заменяет текущий
лимит загруженного экземпляра. Источник:
[LM Studio: список моделей](https://lmstudio.ai/docs/developer/rest/list).

### Точный ID модели и неинтерактивные ошибки

В `prt_15f67273b0019Z0l7UsPVinIUb` абсолютный путь GGUF не совпал с ключом
модели: CLI открыл интерактивный выбор и завершился только по таймауту 300 с.
Новый запуск сервера не использует интерактивный `lms load`. Для управляемого
endpoint точный ключ/ID проверяется перед генерацией: неизвестный,
неоднозначный или не относящийся к LLM идентификатор вызывает отказ.
Автоподстановка похожей модели отсутствует. Обычный
`translate_book.preflight` вне управляемого режима пока лишь предупреждает
об отсутствующем ID — там поведение сторонних совместимых серверов сохранено.

### Повреждённый файл состояния

В `prt_16dda85cd0016WqWhSi9J2YjxY` описан повреждённый
`pipeline.status.json`; `prt_16d6adf53001v3SWc8hg7fh15U` содержит попытку
ручной перезаписи состояния на `interrupted`. В той же сессии применялся
`refresh_state.py`, пересчитывавший сохранённые хэши после изменений кода.
Это исторические обходные действия, **не допустимый рецепт восстановления**.

Текущая атомарная запись снижает риск неполного JSON, а фоновой worker
сохраняет ошибку разбора запуска в журнал и `bootstrap.error.json`.
Для повреждённого состояния самого pipeline добавлена read-only диагностика
`needs_attention` с именем файла, SHA-256 именно прочитанных повреждённых байтов
и местом ошибки JSON. `run/start` отказываются запускать процессы; исходные
байты сохраняются. Восстановление по проверенным стадийным квитанциям остаётся
отдельной будущей операцией; молчаливый сброс на `ready/interrupted` не предусмотрен.

### Геометрия страниц после технической приёмки

`prt_168a91835001FgGuHG5R96MaFg` объявляет техническую приёмку PDF,
после чего пользователь сообщает об обрезанных рисунках
(`prt_168bbec14001DIoI2Ojozb8ngt`). Известные ошибки размеров рисунков и
longtable исправлены и проверены на отдельных фикстурах. В `inspect_pdf` добавлен
контроль растровых размещений по видимой странице (rotation/CropBox, допуск 1 pt).
Выход исходного bbox блокирует выпуск с `needs_review` и координатами. Намеренный
clip/bleed тоже может попасть на проверку: это не доказательство непреднамеренной
потери. Проверка не измеряет текстовое поле, векторные рисунки или перекрытия;
полная визуальная редактура остаётся отдельной необязательной работой.

## Уточнение утверждения о timeout

В старом журнале есть утверждение, будто команда `timeout` посылала Ctrl+C.
Сессия показывает `timeout /t 3 /nobreak` в batch-файле
(`prt_16cf5b6af0016bIBVjSnneNVpX`), а затем объяснение этой командой обрывов
(`prt_16d0baa0c001JoVcaMTGdhC6pW`). Отдельного контрольного опыта,
подтверждающего такую причинность, в выбранных свидетельствах нет.

Microsoft описывает [`timeout.exe`](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/timeout)
как ожидание заданного времени с обработкой нажатий клавиш. Следует различать
эту команду, ограничение времени инструмента и закрытие консоли.
При [закрытии консоли](https://learn.microsoft.com/en-us/windows/console/ctrl-close-signal)
Windows посылает событие всем присоединённым к ней процессам. Именно
независимость от исходной консоли проверяется новым интеграционным тестом.
Вывод «одна Windows-сессия обязательно убивает все процессы» также слишком
широк: задача текущего пользователя может работать в той же сессии входа,
но принадлежать другой консоли и другой цепочке запуска.

## Проверки и оставшаяся работа

1. `tests/test_managed_model_guard.py`: точный ID, фактический loaded context,
   проверки до/после JIT; сценарии 16384 → 8192, неизвестный ID,
   отсутствующий/неоднозначный экземпляр, замену экземпляра с тем же контекстом
   и неполный ответ native API. Отказ сохраняет ранее принятые записи кэша.
   Используются mock-ответы; модели, настройки и кэши пользователя не меняются.
2. `tests/test_pipeline_state_diagnostics.py`: обрезанный JSON, неверный UTF-8,
   JSON не-объект, неизвестная схема, неправильные типы вложенных шагов,
   артефактов, хэшей и идентичностей процессов. `status` возвращает диагностику,
   `run/start` не создают процессов; повреждённые байты остаются идентичными.
3. Геометрические проверки — на новых маленьких PDF с заведомо выходящими
   и корректно расположенными рисунками. Полная книга не используется
   как изменяемый тестовый материал.

# Возобновление после прерывания на настоящей Hy-MT2

Испытание выполнено **15.11.2026**; документация обновлена **16.11.2026**.
Результат: после остановки процесса два принятых абзаца сохранились внутри
ещё не завершённой группы и повторно не отправлялись модели.

Это отдельный прогон после [проверки готового и неполного кэша](LIVE_HYMT_CACHE_CHECK.md).
Алгоритм: [INCREMENTAL_MT.md](INCREMENTAL_MT.md); правила приёмки:
[INTEGRITY.md](INTEGRITY.md); управление запуском: [BACKGROUND_RUN.md](BACKGROUND_RUN.md).

## Условия

- Настоящая локальная `hy-mt2-7b` Q8_0 через LM Studio, `http://localhost:1234`.
- Native API до/после этапов подтвердил ту же модель, выделенный контекст
  16 384 и `parallel=1`.
- `mode=hymt`, `group_chars=900`, `split_chars=280`, `layout=compact`,
  `extract=math`; полировка и облако отключены.
- Новый синтетический Markdown: 855 символов, четыре математических абзаца,
  две формулы. PDF/OCR-извлечение для этого входа не запускалось.
- `split_chars=280` выбран для испытания: одна внешняя группа из четырёх
  абзацев разбилась на четыре запроса. Это параметр теста, не новый default.
  Между остановкой и возобновлением вход, настройки и код оставались прежними.

## Как прервано задание

Задание подготовлено через `pipeline.py init → plan`, запущено командой
`start`. Наблюдатель дождался двух принятых абзацев в `fragments-v1` и начала
третьего HTTP-запроса. В этот момент кэша всей внешней группы, итогового
отчёта MT и PDF ещё не было. На диске сохранились четыре записи: два принятых
запроса и два принятых абзаца.

`pipeline.py stop` завершил собственное дерево процессов этого задания
во время третьего запроса. Проверены PID вместе со временем создания,
завершение всех записанных процессов и удаление одноразовой задачи Планировщика.
Обычный `status` показал `interrupted`; ответ на третий запрос в журнале отсутствовал.
Все четыре уже сохранённых файла кэша совпали с исходными SHA-256.

Остановка подтверждена после ожидания завершения: первый ответ команды `stop`
ещё содержал `running`, поскольку отмена асинхронная. Он означал принятие
запроса на отмену, а не разрешение немедленно запустить второй процесс.

Ответы локальной модели были настоящими. Состояние задания, записи кэша
и их хэши вручную не редактировались; `--force` не использовался.

## Возобновление и число запросов

| Этап | Новые обращения к модели | Проверенный результат |
|---|---:|---|
| До остановки | 3 начатых | Абзацы 1 и 2 приняты; запрос абзаца 3 прерван без ответа |
| `pipeline.py run` того же задания | 2 | Отправлены только абзацы 3 и 4 |
| Повтор готового задания | 0 | Все файлы задания остались побайтно неизменными |

Возобновление с переводом оставшихся абзацев и сборкой PDF заняло **42,255 с**.
Последний повтор — **0,181 с**. Загрузка весов и наблюдения native API
в эти интервалы не входят. Скорость полной книги этим испытанием не измерена.

Оба новых запроса сверены по исходным ID и тексту: принятые абзацы 1 и 2
в них отсутствовали. Их переводы совпали с соответствующими диапазонами
итогового текста побайтно. Четыре прежние записи кэша остались неизменными.
`fragment_cache.reused=2` подтверждает чтение двух принятых запросов внутри
незавершённой группы. Готовая стадия или отчёт целой группы для этого не требовались.

Повторился только запрос третьего абзаца, чей ответ до остановки не был
получен или принят. Четвёртый абзац переведён впервые. Оба ответа после
возобновления: HTTP 200, модель `hy-mt2-7b`, `finish_reason=stop`, текущая
валидация пройдена. Правила приёмки не ослаблялись.

## Приёмка и сохранность

- PDF: 3 страницы, технический release `passed`, обе формулы восстановлены точно.
- `Missing character=0`, `kept_source=0`, список `failed_blocks` пуст;
  подтверждён охват всех четырёх исходных абзацев.
- Закладок 0: в тестовом исходнике нет структурных заголовков.
- SHA-256 PDF: `e6a650aaa0efaf93b090895ff91f8fc563f7c383486925a47303f5f5fb7c48fd`.
- В исходном испытании сверены 7 328 файлов книг и кэшей MRA, 8 исходных
  книг в корне рабочего каталога, 78 файлов кода/ресурсов и 139 файлов
  предыдущего живого теста; все контрольные суммы совпали.
- После испытания его модель выгружена, сервер остановлен, закрытие порта
  1234 подтверждено. Посторонние процессы не завершались.

## Порядок возобновления

Сохранить исходную папку задания и кэш. Проверить `background-status` и
обычный `status`; дождаться завершения отмены и убедиться, что живых дочерних
процессов нет. При `interrupted` повторить штатный `run` того же задания
с прежними параметрами. Для оставшихся запросов должен быть доступен выбранный
endpoint. При `needs_attention` сначала разобрать указанную причину.

Не пересоздавать готовые фрагменты, не менять ключи/хэши и не очищать кэш
ради возобновления. Повтор ещё не принятого запроса ожидаем; повтор уже
принятого текста проверять по журналу и идентичности настроек/источника.
Конкретные команды и условия: [BACKGROUND_RUN.md](BACKGROUND_RUN.md).

## Границы и свидетельства

Проверено завершение клиентского процесса в Windows после сохранения хороших
фрагментов и до фиксации всей группы. Отключение питания, повреждение диска
или потеря несохранённых буферов ОС не моделировались. Ошибочный ответ модели,
повреждённый кэш и смена политики покрыты отдельными регрессиями с mock HTTP.
Полная смысловая и визуальная редактура тестового перевода не выполнялась.

В рабочей установке исходные свидетельства сохранены во внешней папке
`maintenance/20261115_live_hymt_interrupt`: `interruption-trigger.json`,
результаты остановки/возобновления/повтора, `summary.json`, отчёт сохранности,
`cleanup.json`, исходник, настройки, скрипты испытания и журналы `*.attempts`.
В переносимый пакет входит это описание. Сырые ответы, тестовый PDF, кэши
и скрипты, привязанные к локальным путям, остаются вне архива. Новое испытание
проводить в новой папке; исходные свидетельства не перезаписывать.

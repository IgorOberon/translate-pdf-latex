# Живая проверка Hy-MT2 и повторного использования перевода

15 ноября 2026 года выполнен малый EN→RU прогон на настоящей локальной
`hy-mt2-7b` Q8_0. Подтверждены повтор готового задания без новых запросов
и сохранение принятых абзацев при заполнении неполного кэша.
Алгоритм и правила валидации: [INCREMENTAL_MT.md](INCREMENTAL_MT.md),
[INTEGRITY.md](INTEGRITY.md).

Дополнение документации 16.11.2026: отдельно выполнена
[живая проверка возобновления после остановки процесса](LIVE_HYMT_INTERRUPT_CHECK.md).
Ниже сохранены условия и результаты первого прогона с готовым/неполным кэшем.

## Условия

- Windows, NVIDIA GeForce RTX 5060 Ti с 16 ГБ VRAM, установленный LM Studio.
- Endpoint `http://localhost:1234`; модель и выделенный контекст проверены
  через native API до и после запусков: `hy-mt2-7b`, 16 384 токена, `parallel=1`.
- `mode=hymt`, `group_chars=900`, `split_chars=900`, `layout=compact`,
  `extract=math`, `temperature=0.7`, `top_p=0.6`.
- Полировка и облако отключены. Ответы получены напрямую от локальной модели,
  без mock-сервера или промежуточного HTTP-прокси.
- Новый синтетический Markdown: 1 217 символов, заголовок и четыре
  математических абзаца, три формулы и числовые значения.
  Параметр `extract=math` сохранён в настройках, но для Markdown PDF/OCR-движок
  не запускался. Проверка не подтверждает качество извлечения из PDF.

## Результаты

| Запуск | Новые запросы к модели | Время команды | Проверенный результат |
|---|---:|---:|---|
| Первый `pipeline.py run` | 3 | 60,464 с | Перевод и сборка PDF; статус `done` |
| Повтор того же задания | 0 | 0,219 с | Все файлы задания остались побайтно неизменными |
| MT с неполной копией кэша | 1 | 7,341 с | Переведён только недостающий абзац |
| Повтор MT после заполнения кэша | 0 | 0,381 с | Повторно использованы две проверенные группы; перевод неизменен |

Время измерено вокруг команды процесса; загрузка весов, запуск LM Studio и
наблюдения native API в него не входят. Последние две строки относятся только
к MT, без сборки PDF. Суммарное HTTP-время трёх первых запросов — около 26,17 с.
Все три ответа: HTTP 200, `finish_reason=stop`, reasoning-токенов нет.
Это измерение данного фрагмента, а не обещание скорости перевода книги.

## Что доказывает проверка неполного кэша

Первый прогон выполнен через `pipeline.py init → plan → run → status`.
Повтор `run` проверил контрольную точку готового задания: новых запросов,
проходов TeX или изменений PDF не было. Этот результат сам по себе проверяет
пропуск готовой стадии, поэтому дополнительно проверен кэш внутри стадии MT.

В новую отдельную папку скопированы четыре принятые записи `paragraph-piece`:
заголовок и три абзаца. Их байты и хэши не менялись. Запись последнего абзаца,
кэши целых запросов/групп, готовый перевод и его отчёт не копировались.
Исходные кэш и задание сохранены целиком. Штатный `translate.py` получил тот же
маскированный источник и те же параметры, но новый выходной файл.

Единственный новый запрос точно совпал с сообщениями штатного планировщика
для недостающего абзаца, включая его ID. Четыре готовых фрагмента не вошли
в запрос и сохранили прежние хэши в результате. Затем повторный MT не сделал
новых запросов. Валидация не ослаблялась, идентичность запросов не подменялась.

`fragment_cache.reused=8` в первом частичном прогоне означает восемь чтений
четырёх уникальных записей при поиске и сборке. Это не восемь разных абзацев.
`from_cache` считает внешние группы; его нельзя напрямую складывать с
чтениями фрагментов или числом HTTP-запросов.

## Приёмка и границы вывода

- PDF принят технически: 3 страницы, 1 закладка, все 3 формулы восстановлены точно.
- `Missing character`: 0; `kept_source`: 0; `failed_blocks`: пуст.
- Проверены происхождение перевода и охват всех пяти исходных единиц.
- SHA-256 PDF: `f7a2477abf5c57e5fd4fc516353017088e73ef77f5e9026e02fe168120831e03`.
- После теста загруженная для него модель выгружена, сервер остановлен.

Этот первый живой прогон проверяет положительный сценарий и отсутствие одной записи кэша.
Ошибочный ответ модели, повреждённый кэш, более строгая политика и аварийное
прерывание здесь не вызывались: эти сценарии проверяются отдельно регрессиями
с mock HTTP. Полная смысловая/визуальная редактура и скорость полной книги
не оценивались. Технический успех не доказывает безошибочность перевода.

Завершение процесса во время HTTP-запроса и последующее возобновление
проверены в [отдельном испытании](LIVE_HYMT_INTERRUPT_CHECK.md); его результат
не означает проверки отключения питания или повреждения диска.

## Свидетельства и повтор на другой установке

В рабочей установке свидетельства сохранены в
`maintenance/20261115_live_hymt_cache`: исходник и настройки, снимки native API,
журналы `*.attempts`, отчёты четырёх запусков, `partial-cache-seed.json`,
`summary.json`, `RESULT.md` и `cleanup-verified.json`.
Это внешняя папка испытания, не часть переносимого пакета. В архив входит
данное описание; сырые ответы, кэши, локальные пути окружения и тестовый PDF
не требуются для работы движка и не экспортируются.

Для новой проверки использовать новый короткий синтетический вход и новую
папку задания. Явно задать модель/endpoint и фактический выделенный контекст,
сохранить настройки между запусками. Сравнивать новые записи запросов и хэши
PDF/перевода до и после повторного `run`; одного статуса `done` недостаточно
для измерения работы кэша внутри MT. Проверку неполного кэша выполнять только
на отдельной копии принятого тестового кэша, не удаляя записи исходного задания.
При отказе сохранить журнал и разобрать причину, без `--force`, подмены хэшей
или автоматического перехода на другую модель.
